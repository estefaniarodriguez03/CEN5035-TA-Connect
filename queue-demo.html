Queue Realtime Demo

Queue status (from API): —

Open — students may join. Paused / Closed — join returns 409 (queue is paused / queue is closed). TAs change state with PATCH below.

Role-based access (auth middleware)

Every protected route runs through two middlewares: RequireAuth (validates the Bearer token) and RequireRole(...). Failures return structured JSON.

  • 401 (no/invalid token): {"error":"...","code":"auth_required"}
  • 403 (wrong role): {"error":"...","code":"role_forbidden","required_role":"ta"}
  • 403 (not the resource owner): {"error":"...","code":"not_queue_owner"} or "not_resource_owner"
  • TA-only routes: POST /api/queues, PATCH /api/queues/:id/state, POST /api/queues/:id/next, POST /api/queues/:id/announcement, POST|PUT|DELETE /api/office-hours[/:id]
  • Student-only routes: POST /api/queues/:id/join, POST /api/queues/:id/leave
  • Public: GET /api/queues/:id, GET /api/queues/active, GET /api/queues/:id/events (SSE), GET /api/office-hours/...

    Queue management

    Must be logged in as a TA; on success, Queue ID field above is set to the new queue id.

    Queue actions

    SSE listens for: STUDENT_JOINED, STUDENT_LEFT, STUDENT_SERVED, STUDENT_UP_NEXT, ANNOUNCEMENT_SENT, QUEUE_UPDATED, QUEUE_STATE_CHANGED (payload: previous_status, status). Each data: line is the full JSON envelope (type, queue_id, payload).

    Queue state (TA only)

    PATCH /api/queues/:id/state — body {"status":"open"|"paused"|"closed"}

    Legacy POST /api/queues/:id/status with the same JSON still works; this page uses PATCH /state.

    Join/leave are student-only — calling them with a TA token will produce a structured 403 with code: "role_forbidden" and required_role: "student" (shown in the red banner above). A second join by the same student hits the UNIQUE(queue_id, student_id) DB constraint and returns 409 "already in queue".

    Concurrent-join stress test

    Registers N fresh students and fires their POST /join requests in parallel against the current Queue ID. Thanks to the DB transaction + SELECT ... FOR UPDATE on the queue row, every student gets a unique, contiguous position (1..N) even when requests race.

    Notifications: announcement API

    Manual smoke test: (1) Connect to /events. (2) As a student, Join — expect STUDENT_JOINED, QUEUE_UPDATED, and STUDENT_UP_NEXT with payload.student_id / position: 1 for whoever is at the front of the line. (3) As the queue-owning TA, send an announcement — expect ANNOUNCEMENT_SENT then QUEUE_UPDATED. (4) As TA, Next — expect STUDENT_SERVED then QUEUE_UPDATED; if someone is still waiting, STUDENT_UP_NEXT names the new person at position 1 only. (5) As TA, set Pause or Close — badge updates; SSE shows QUEUE_STATE_CHANGED then QUEUE_UPDATED. Try Join as a student → 409 with a clear message. Set Open again to allow joins.
